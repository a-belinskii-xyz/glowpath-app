================================================================================
GlowPath — ТЗ: контент-пакеты онбординга (теги, шаблоны заметок, цели)
================================================================================
Версия: 1.0
Назначение: отдать другому ИИ-агенту как бриф на генерацию исходных шаблонов.
Языки контента: en + ru (обязательно оба).
Продукт: GlowPath — персональный трекер настроения (score 1–5 + заметка + теги + цели).


--------------------------------------------------------------------------------
1. КОНТЕКСТ ПРОДУКТА
--------------------------------------------------------------------------------

Пользователь логирует записи настроения:
  - score: 1–5
  - note: markdown (опционально)
  - tags: контекстные метки из групп
  - goals: опциональная привязка к недельным целям

Теги объясняют КОНТЕКСТ настроения (что происходило / как себя чувствовал /
где был / чем занимался). Они НЕ заменяют score.

Шаблоны заметок (note templates) — markdown-заготовки, которые пользователь
вставляет в поле note. Не привязаны к записям.

Цели (goals) — привычки с частотой times_per_week (1–7). Можно отмечать
в записи настроения.

При регистрации сейчас всегда провижинятся одни и те же базовые дефолты
(см. раздел 3). Нужен онбординг:

  A) Пользователь ПРОПУСТИЛ онбординг
     → только BASE-пакет (текущие дефолты, возможно слегка расширенные).

  B) Пользователь ПРОШЁЛ онбординг
     → BASE + выбранные INTEREST/LIFE-пакеты (без дублей slug).

Ограничения UI (важны при генерации):
  - На форме записи видно максимум ~6 групп тегов (show_on_entry).
  - Целей на форме / в статистике тоже лимит (обычно первые по sort_order).
  - Не раздувать: лучше 3–6 релевантных групп, чем 15 бесполезных.
  - В группе обычно 3–6 тегов (иногда до 8). Не делать «словари».


--------------------------------------------------------------------------------
2. ФОРМАТ ДАННЫХ (строго соблюдать при генерации)
--------------------------------------------------------------------------------

Общие правила:
  - slug: snake_case, латиница, [a-z0-9_], длина ≤ 64, уникален
    в своём скоупе (группа — у пользователя; тег — внутри группы;
    шаблон/цель — у пользователя).
  - labels / bodies: JSON-объект {"en": "...", "ru": "..."}.
  - color: hex #RRGGBB.
  - icon_type: всегда "emoji".
  - icon: один emoji (или emoji-последовательность вроде 😮‍💨).
  - Тон: нейтральный, поддерживающий, без клинической лексики
    («депрессия», «диагноз» и т.п.). Можно «тревога», «усталость», «выгорание»
    как самоощущение — осторожно, без стигмы.
  - RU и EN должны быть смысловыми эквивалентами, не калькой с ошибками.
  - Шаблоны: короткие markdown-скелеты с заголовками ## и пустыми строками
    под ответ. Без заполненного «примера жизни».

--- TagGroup ---
{
  "slug": "weather",
  "labels": {"en": "Weather", "ru": "Погода"},
  "show_on_entry": true,          // приоритет для формы записи
  "sort_order": 0,
  "tags": [ Tag, ... ]
}

--- Tag ---
{
  "slug": "sunny",
  "labels": {"en": "Sunny", "ru": "Солнечно"},
  "color": "#f59e0b",
  "icon_type": "emoji",
  "icon": "☀️",
  "sort_order": 0
}

--- NoteTemplate ---
{
  "slug": "gratitude",
  "labels": {"en": "Gratitude", "ru": "Благодарность"},
  "bodies": {
    "en": "## Three things I'm grateful for\n\n1. \n2. \n3. \n",
    "ru": "## Три вещи, за которые я благодарен\n\n1. \n2. \n3. \n"
  },
  "sort_order": 0
}

--- Goal ---
{
  "slug": "exercise",
  "labels": {"en": "Exercise", "ru": "Тренировка"},
  "times_per_week": 3,            // integer 1..7
  "color": "#34d399",
  "icon_type": "emoji",
  "icon": "🏃",
  "show_on_entry": true,
  "show_in_stats": true,
  "sort_order": 0
}

--- ContentPack (единица генерации) ---
{
  "pack_id": "interest.gaming",     // стабильный id пакета
  "kind": "base" | "life" | "interest" | "focus",
  "title": {"en": "...", "ru": "..."},
  "description": {"en": "...", "ru": "..."},   // для UI онбординга / документации
  "onboarding_triggers": ["..."],   // ключи ответов онбординга (см. §5)
  "priority": 100,                  // выше = важнее при отборе show_on_entry
  "tag_groups": [ TagGroup, ... ],
  "note_templates": [ NoteTemplate, ... ],
  "goals": [ Goal, ... ]
}

          default_note_templates.py, default_goals.py

--------------------------------------------------------------------------------
5. МОДЕЛЬ ОНБОРДИНГА (вопросы → пакеты)
--------------------------------------------------------------------------------

Онбординг — короткий мультивыбор. Пользователь может выбрать несколько
ответов в каждом блоке. Skip = только BASE.

Рекомендуемые блоки вопросов (keys стабильные):

БЛОК A — «Чем ты в основном занят?» (life, 1–2 ответа)
  life.office          Офис / удалёнка / корпорат
  life.student         Учёба
  life.freelance       Фриланс / свой проект
  life.shift           Сменный / нерегулярный график
  life.parent          Забота о детях / семье
  life.between         Переходный период / поиск себя

БЛОК B — «Что важно отслеживать рядом с настроением?» (focus, 1–3)
  focus.sleep          Сон и восстановление
  focus.stress         Стресс и тревога
  focus.energy         Энергия и выгорание
  focus.social         Отношения и общение
  focus.body           Тело / самочувствие
  focus.habits         Привычки и дисциплина
  focus.emotions       Эмоции подробнее

БЛОК C — «Чем любишь заниматься?» (interest, 0–4)
  interest.gaming      Игры
  interest.sport       Спорт / тренировки
  interest.outdoors    Природа / прогулки
  interest.creative    Творчество (рисование, музыка, письмо…)
  interest.reading     Чтение / учёба ради интереса
  interest.food        Еда / готовка
  interest.media       Фильмы / сериалы / подкасты
  interest.music       Музыка (слушаю / играю)
  interest.travel      Поездки / дорога
  interest.social_hobbies  Компании / тусовки / хобби с людьми

Правило сборки профиля:
  packs = {BASE}
  + life-пакеты по выбранным A
  + focus-пакеты по выбранным B
  + interest-пакеты по выбранным C

Дедупликация:
  - одинаковые slug групп/тегов/шаблонов/целей — оставить один экземпляр
    (побеждает пакет с более высоким priority, либо BASE).
  - если life и interest предлагают похожую группу (например sport) —
    мержить теги в одну группу или оставить более специфичную;
    в ТЗ на генерацию: делать slug'и ортогональными, чтобы мерж был редким.

Лимит show_on_entry для групп тегов после сборки:
  1) Всегда включить mood + sleep_quality (если есть)
  2) Затем группы из выбранных пакетов по priority
  3) Остальное show_on_entry=false (пользователь может включить позже)
  Цель: ≤ 6 групп на форме.


--------------------------------------------------------------------------------
6. ЧТО НУЖНО СГЕНЕРИРОВАТЬ (КАТАЛОГ ПАКЕТОВ)
--------------------------------------------------------------------------------

Для КАЖДОГО pack_id ниже сгенерировать полный ContentPack в JSON
(см. формат §2 и §8).

Объём на пакет (ориентир, не жёсткий закон):
  - tag_groups: 1–2 группы (BASE — исключение, 4 группы)
  - tags per group: 3–6
  - note_templates: 0–2 (не у всех пакетов нужны)
  - goals: 0–2

Не генерировать пустые пакеты «ради галочки». Если интерес почти не
добавляет ценности сверх BASE activity — всё равно дать 1 узкую группу
+ 1 шаблон ИЛИ 1 цель.

--------------------------------------------------------------------------------
6.1 BASE (обязательный)
--------------------------------------------------------------------------------
pack_id: base.default
kind: base
triggers: (всегда)

Задача агента:
  - Зафиксировать текущие 4 группы + 3 шаблона + 3 цели как канон.
  - ОПЦИОНАЛЬНО предложить мягкое расширение BASE (отдельным списком
    «proposed_base_additions»), например:
      * mood: добавить sadness / irritation (если не раздувать)
      * activity: study / chores
      * новая группа people (family / friends / alone) — спорно для BASE;
        лучше оставить для focus.social
  - Не удалять существующие slug'и BASE.

7. ПРАВИЛА КАЧЕСТВА КОНТЕНТА
--------------------------------------------------------------------------------

1) Практичность: тег должен быть тем, что человек реально отметит за 1 тап
   рядом с настроением. Не «метафизика», не редкие события раз в год.

2) Ортогональность: группы отвечают на разные вопросы
   (как спал? / где был? / с кем? / чем занимался? / что чувствую детально?).

3) Без пересечения slug между пакетами, кроме осознанного наследования BASE.
   Если два пакета хотят "friends" — один slug, один пакет-владелец
   (обычно focus.social).

4) Цвета: различимые внутри группы; не делать все фиолетовыми.
   Палитра-ориентир уже в BASE (#f59e0b, #94a3b8, #60a5fa, #6366f1,
   #34d399, #f87171, #a78bfa, #f472b6, #d97706).

5) Иконки: узнаваемый emoji, без дублей внутри одной группы по возможности.

6) Шаблоны: 2–4 секции ##, пустые строки для ответа, без стен текста.
   Длина body ≈ 3–8 строк markdown.

7) Цели: реалистичные times_per_week; формулировка — действие, не результат
   («Прогулка», не «Стать счастливее»).

8) Локализация:
   - RU: естественный русский, «ты»-нейтральные формулировки или безличные.
   - EN: простой international English.
   - Gender: избегать форм, ломающихся по роду; предпочитать
     «Хорошо поспал(а)» ЛИБО безличные «Хороший сон» —
     в текущем BASE уже есть «Хорошо поспал» — для новых тегов
     предпочтительнее нейтраль: «Хороший сон», «Плохой сон», «Тренировка».

9) Безопасность: не обещать лечение, не стыдить за еду/игры/скролл.
   Игры и медиа — валидный досуг; лимиты — опциональные цели, не мораль.

10) Имена пакетов и title/description — пригодны для UI мультивыбора
    (короткие, 1–4 слова в title).

9. ПРИМЕРЫ СБОРКИ ПРОФИЛЕЙ (acceptance scenarios)
--------------------------------------------------------------------------------

Scenario S0 — Skip onboarding
  packs: base.default
  Ожидание: 4 группы (weather, sleep_quality, mood, activity),
             3 шаблона, 3 цели. Все 4 группы show_on_entry=true.

Scenario S1 — «Офис + стресс + игры»
  answers: life.office, focus.stress, interest.gaming
  packs: base + life.office + focus.stress + interest.gaming
  Ожидание:
    - есть gaming-теги и work_context/focus_at_work
    - есть stress/coping теги
    - show_on_entry: mood, sleep_quality + до 4 из пакетных групп
      (gaming и work_context приоритетнее weather/activity при нехватке слотов —
       weather можно оставить false)
    - шаблоны: BASE + after-session + stress unload + end-of-workday
      (если слишком много — ок, шаблоны не лимитируются формой так жёстко)
    - цели: без дублей slug с BASE

Scenario S2 — «Студент + сон + чтение»
  packs: base + life.student + focus.sleep + interest.reading
  Ожидание: study + sleep_factors + reading; цели про сон/учёбу/чтение.

Scenario S3 — «Родитель + отношения + еда»
  packs: base + life.parent + focus.social + interest.food
  Ожидание: family_care + people + food; тон заботливый, без стыда.

Scenario S4 — Только interests без life/focus
  answers: interest.outdoors, interest.music
  packs: base + оба interest
  Ожидание: работает; BASE остаётся опорой.
