# Deploying GlowPath

## Production at a glance

| Piece | Where | Notes |
|-------|-------|-------|
| Frontend (nginx + SPA) | Render web service, https://mood-tracker-l17s.onrender.com | `frontend/Dockerfile`; nginx proxies `/v1` to `API_UPSTREAM` |
| API | Render web service, https://mood-tracker-back.onrender.com | `backend/Dockerfile`; runs `alembic upgrade head` on every start |
| Telegram bot | Render web service | `telegram-bot/Dockerfile`; registers its webhook on start |
| Postgres | Neon, eu-central-1 | pooled `DATABASE_URL` for the app, direct `DATABASE_URL_UNPOOLED` for migrations |
| File storage | Hosted S3-compatible object storage | `MINIO_*` variables, `MINIO_SECURE=true` |
| Reminder worker | not deployed | Render has no free worker plan; `FEATURE_NOTIFICATIONS_ENABLED=false` |
| Semantic search | off | `EMBEDDING_ENABLED=false`: free instances have 512 MB RAM and no disk |

All services run in Frankfurt on the free plan and sleep when idle, so the first request after a pause waits for a cold start.

The Blueprint (`render.yaml`) names the services `glowpath-api`, `glowpath-web` and `glowpath-bot`; the live hostnames differ. Treat the dashboard as the source of truth for what is actually configured.

## Deploying a change

1. Merge to `main`. There is no CI in the repo, so run `make lint typecheck test` and `make frontend-build` before merging.
2. Render builds and deploys each service from `main`.
3. The API applies pending migrations on start (through `DATABASE_URL_UNPOOLED` when set). If a migration fails, the new instance does not come up; check the deploy log.
4. Smoke check:
   ```bash
   curl https://mood-tracker-back.onrender.com/health
   curl https://mood-tracker-l17s.onrender.com/v1/health   # through nginx
   ```

Because migrations run on start, split destructive schema changes across two releases: first ship code that works with both schemas, then drop the old one.

## Environment variables

All backend variables are defined in `backend/app/config.py` and documented in `backend/.env.example`.

### API

| Variable | Value | Needed for |
|----------|-------|-----------|
| `DATABASE_URL` | Neon pooled URL (`postgresql://` is rewritten to psycopg 3) | everything |
| `DATABASE_URL_UNPOOLED` | Neon direct host (no `-pooler`) | migrations |
| `JWT_SECRET_KEY` | generated by the Blueprint | auth |
| `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET`, `MINIO_SECURE=true` | storage provider | photos, audio, icons |
| `FRONTEND_URL`, `CORS_ORIGINS`, `APP_PUBLIC_URL` | frontend public URL | links in emails, CORS |
| `APP_DEBUG` | `false` | |
| `EMBEDDING_ENABLED` | `false` | |
| `FEATURE_NOTIFICATIONS_ENABLED` | `false` until a worker runs | reminders |
| `TELEGRAM_BOT_SERVICE_TOKEN` | same value as on the bot | bot → API calls |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | BotFather | Mini App sign-in (`initData` check) and account linking |
| `TELEGRAM_MINI_APP_URL` | frontend public URL | Mini App buttons |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM` | mail provider | email verification, password reset |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` | Google Cloud | Google sign-in (optional) |
| `TELEGRAM_OIDC_CLIENT_ID`, `TELEGRAM_OIDC_CLIENT_SECRET`, `TELEGRAM_OIDC_REDIRECT_URI` | BotFather Login Widget | Telegram sign-in on the website (optional) |
| `GUEST_EXPERIMENT_SECRET` | random string | guest experiment, if enabled |
| `BILLING_DEFAULT_PROVIDER`, `BILLING_ENABLED_PROVIDERS` | see warning below | plans |

`render.yaml` does not declare the Telegram token and username, `TELEGRAM_MINI_APP_URL`, SMTP, OAuth, `GUEST_EXPERIMENT_SECRET` or billing variables; they have to be added in the dashboard.

> **Billing:** the default provider is `fake`, which completes checkout instantly without payment and accepts unsigned webhooks. Do not leave `fake` enabled in production once paid plans are visible to users.

Production redirect URIs:

- Google: `https://mood-tracker-back.onrender.com/v1/auth/google/callback`
- Telegram OIDC: `https://mood-tracker-back.onrender.com/v1/auth/telegram/callback`

### Frontend

| Variable | Value |
|----------|-------|
| `API_UPSTREAM` | `https://mood-tracker-back.onrender.com` |

The image is built with an empty `VITE_API_BASE_URL`, so the browser always calls `/v1` on its own origin.

### Telegram bot

| Variable | Value |
|----------|-------|
| `API_BASE_URL` | API public URL |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_SERVICE_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` | secrets |
| `TELEGRAM_WEBHOOK_URL` | the bot's own public origin, without the path |
| `TELEGRAM_MINI_APP_URL` | frontend public URL |

In BotFather set **Menu Button** and **Main Mini App** to the frontend URL, then check the webhook:

```bash
curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getWebhookInfo"
```

## Catalog data

Marketplace packs and achievements are loaded by seed commands, not by migrations, and have not been run in production yet:

```bash
python -m app.services.marketplace_seed      # backend/app/data/marketplace/
python -m app.services.achievements.seed     # after the packs
```

The free plan has no Shell, so run them from a local checkout with `backend/.env` pointing at the production `DATABASE_URL` and `MINIO_*`, or export a preset locally (`make preset-export`) and import it against production (`make preset-import`).

## First-time setup

1. Create a Neon project in eu-central-1; copy the pooled and direct URLs.
2. Create an S3-compatible bucket and access keys.
3. Render → New → Blueprint → this repo. Fill every `sync: false` variable.
4. Add the variables `render.yaml` does not declare (see above).
5. After the first deploy, point BotFather at the frontend URL and confirm `getWebhookInfo`.
6. Load the catalog data.

## Alternative: one server with Docker Compose

`docker-compose.prod.yml` runs migrations, the API, the reminder worker, the nginx frontend and the bot on one machine. Postgres and storage stay external.

```bash
cp .env.prod.example .env.prod        # PUBLIC_URL, DATABASE_URL*, MINIO_*, SMTP_*
cp backend/.env.example backend/.env  # JWT, Telegram, OAuth secrets
docker compose -f docker-compose.prod.yml --env-file .env.prod up --build -d
docker compose -f docker-compose.prod.yml --env-file .env.prod logs -f --tail=100
```

`PUBLIC_URL` sets `FRONTEND_URL`, `CORS_ORIGINS`, `APP_PUBLIC_URL` and the Mini App URL. Put TLS in front (Caddy or nginx on 443): Telegram webhooks and the browser's `crypto.randomUUID()` need HTTPS. Add `--profile mail` only for a local smoke test with MailHog. Unlike Render free, this path runs the reminder worker.

The frontend is static inside its image, so every change needs `--build`.

## Known risks

- Free instances sleep; the first bot webhook after idle waits for a cold start and Telegram may retry it.
- No reminder worker in production, so reminders are off.
- `fake` billing completes checkout without payment (see above).
- No CI: nothing runs tests before Render deploys `main`.
